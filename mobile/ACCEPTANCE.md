设备登录初验发现学校认证会重定向到 `analytics.ustc.edu.cn/.isg/gateway/sso-init`，初版导航限制导致空白页。用户先要求放宽到学校二次认证，随后明确要求“跳转不要有任何限制”。最终已删除全部应用层导航白名单，也允许网页自动新窗口在同一WebView内打开；认证/教务两域的Cookie读取限制与系统TLS校验保留。随后小蜗报“暂时无法核验学校身份”，根因为成功探测会话后未更新 CASClient 登录标记，导致身份接口被本地检查拒绝；最小修复后，用户确认小蜗登录和本人课表成功。

继续检查时还发现教务dataId未被会话恢复与线程克隆携带，已补齐私有缓存、密文payload及线程传递，不改问答/工具逻辑。新授权要求学校验证的正整数dataId；旧开发会话缺字段会要求重新登录。本机已存在的1条真实会话经同一学校会话只读重验、校验学号一致后更新密文，token不变，未写出凭据；本机后端已重启采用补丁。

发行构建已用保留测试域 `https://example.invalid/api/v1` 编译验证（不发请求、不安装），默认无发行签名；直接使用debug网页资源执行release的检查按预期失败。验证包明确标为 `validation-only`，不能用作正式发行；正式服务地址仍待申请。

CI 工作流已提供，但本地尚未推送，不能声称 GitHub Actions 已运行。发行签名、正式服务域名、隐私政策运营主体和 iOS 原生桥均不冒充已具备。
