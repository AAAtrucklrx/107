# 小蜗 — 技术架构文档

> 本文档定义"小蜗"项目的技术方案，面向开发者（团队成员 + AI Agent）。
> 参考：myshare.md — 技术栈选择要有理由，架构设计要清晰到AI能直接实现。

---

## 一、技术栈选型

| 层次 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| 语言 | Python | 3.10+ | 团队熟悉、LangChain生态最好 |
| Agent框架 | LangChain | 0.3+ | AI Agent开发的事实标准，文档完善，社区活跃 |
| LLM接入 | OpenAI兼容API | — | 校内llm.ustc.edu.cn提供OpenAI兼容接口 |
| 前端 | Streamlit | 1.30+ | 纯Python写界面，学习成本最低，10分钟出原型 |
| 数据库 | SQLite | (内置) | 零配置、文件级存储、Python内置支持 |
| 向量数据库 | ChromaDB | 0.5+ | 轻量级、Python原生、无需单独部署 |
| Embedding | text2vec-base-chinese | — | 中文语义向量，本地运行无需API |
| 爬虫 | requests + BeautifulSoup | — | 轻量级，评课社区数据量不大 |
| 包管理 | pip + requirements.txt | — | 标准方案 |

### 不选型的理由（同样重要）

| 技术 | 为什么不选 |
|------|-----------|
| FastAPI / Flask | 增加前后端分离复杂度，Streamlit一体搞定 |
| MySQL / PostgreSQL | 需要单独数据库服务，SQLite够用且零配置 |
| React / Vue | 团队没有前端经验，Streamlit纯Python |
| LangGraph | 小蜗的Agent路由不复杂，不需要状态图 |
| Pinecone / Weaviate | 需要云端部署，ChromaDB本地跑足够 |

## 二、Agent 架构设计

### 2.1 总体架构

```
┌─────────────────────────────────────────────┐
│                 Streamlit 前端               │
│   ┌─────────────────────────────────────┐   │
│   │         对话界面 + 侧边栏             │   │
│   └──────────────┬──────────────────────┘   │
│                  │ 用户输入                   │
│   ┌──────────────▼──────────────────────┐   │
│   │            主Agent（路由器）          │   │
│   │   - 理解用户意图                     │   │
│   │   - 路由到对应子Agent                │   │
│   │   - 整合子Agent返回的结果            │   │
│   └───┬──────────┬──────────┬───────────┘   │
│       │          │          │               │
│  ┌────▼───┐ ┌───▼────┐ ┌───▼────┐ ┌──────▼──┐
│  │智能问答 │ │课业助手 │ │选课顾问 │ │ 日程管理 │
│  │ Agent  │ │ Agent  │ │ Agent  │ │  Agent  │
│  └────┬───┘ └───┬────┘ └───┬────┘ └────┬─────┘
│       │         │         │         │
│       ▼         ▼         ▼         ▼
│  ┌─────────────────────────────────────────┐
│  │              Tool 工具层                  │
│  │  search_faq / query_schedule /           │
│  │  recommend_courses / add_event / ...     │
│  └──────────────┬──────────────────────────┘
│                 │
│  ┌──────────────▼──────────────────────────┐
│  │              数据层                      │
│  │  ChromaDB(向量) + SQLite(结构化) + API   │
│  └─────────────────────────────────────────┘
```

### 2.2 主Agent路由逻辑

```python
# 主Agent的System Prompt中包含路由规则
ROUTER_PROMPT = """
你是一个路由器Agent。根据用户输入，判断应该由哪个子Agent处理。

路由规则：
1. 用户问"xxx是什么/怎么办/在哪里/流程/规定/政策" → 智能问答Agent
2. 用户问"我的课表/成绩/GPA/空教室/考试" → 课业助手Agent
3. 用户问"推荐课程/对比课程/老师怎么样/选课建议" → 选课顾问Agent
4. 用户问"日程/提醒/今天/明天/这周/添加事件/导入课表" → 日程管理Agent
5. 无法判断 → 由智能问答Agent兜底处理

输出格式（严格遵守）：
{
    "agent": "faq" | "course" | "advisor" | "schedule",
    "reason": "简要说明路由原因",
    "rewritten_query": "如有必要，改写为用户意图更清晰的query"
}
"""
```

### 2.3 子Agent的Tool配置

每个子Agent只暴露自己模块的Tool，互不交叉：

| 子Agent | 可用的Tool |
|---------|-----------|
| 智能问答Agent | `search_faq`, `get_faq_categories` |
| 课业助手Agent | `query_schedule`, `find_empty_room`, `query_grade`, `calc_gpa`, `query_exam` |
| 选课顾问Agent | `recommend_courses`, `compare_courses`, `analyze_teacher` |
| 日程管理Agent | `add_event`, `get_day_view`, `get_week_view`, `check_conflict`, `import_schedule` |

## 三、数据库 Schema

### 3.1 完整建表SQL

```sql
-- ============================================
-- 课业相关
-- ============================================

-- 课程信息缓存表
CREATE TABLE IF NOT EXISTS courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code TEXT UNIQUE,              -- 课程编号
    name TEXT NOT NULL,            -- 课程名
    teacher TEXT,                  -- 教师
    credits REAL,                  -- 学分
    time TEXT,                     -- 上课时间
    location TEXT,                 -- 上课地点
    semester TEXT,                 -- 学期
    capacity INTEGER,              -- 容量
    description TEXT               -- 课程简介
);

-- 学生课表关联表（第一版只有一个演示学生）
CREATE TABLE IF NOT EXISTS student_courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id TEXT NOT NULL,
    course_code TEXT NOT NULL,
    course_name TEXT NOT NULL,
    teacher TEXT,
    credits REAL,
    time TEXT,
    location TEXT,
    semester TEXT DEFAULT '2025-2026-2'
);

-- 学生成绩表
CREATE TABLE IF NOT EXISTS student_grades (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id TEXT NOT NULL,
    semester TEXT NOT NULL,
    course_name TEXT NOT NULL,
    credits REAL NOT NULL,
    score INTEGER NOT NULL,
    grade_point REAL NOT NULL     -- 科大4.3制
);

-- 评课社区数据缓存表
CREATE TABLE IF NOT EXISTS course_reviews (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    course_code TEXT,
    course_name TEXT NOT NULL,
    teacher TEXT,
    rating REAL,                  -- 综合评分 1-10
    difficulty REAL,              -- 难度 1-10
    workload REAL,                -- 工作量 1-10
    give_score TEXT,              -- 给分评价
    tags TEXT,                    -- 标签（逗号分隔）
    review_count INTEGER DEFAULT 0,
    review_summary TEXT,          -- AI总结的评价摘要
    last_updated TEXT
);

-- 教师评价缓存表
CREATE TABLE IF NOT EXISTS teacher_reviews (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    courses TEXT,                 -- 所授课程（逗号分隔）
    avg_rating REAL,
    teaching_style TEXT,
    strengths TEXT,
    weaknesses TEXT,
    review_summary TEXT,
    review_count INTEGER DEFAULT 0
);

-- ============================================
-- 日程相关
-- ============================================

CREATE TABLE IF NOT EXISTS events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id TEXT NOT NULL,
    title TEXT NOT NULL,
    event_type TEXT NOT NULL,     -- "course" | "exam" | "homework" | "custom"
    start_time TEXT NOT NULL,     -- ISO格式
    end_time TEXT NOT NULL,
    location TEXT,
    description TEXT,
    is_recurring INTEGER DEFAULT 0,
    source TEXT DEFAULT 'manual',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS reminders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_id INTEGER NOT NULL,
    remind_at TEXT NOT NULL,
    is_triggered INTEGER DEFAULT 0,
    FOREIGN KEY (event_id) REFERENCES events(id)
);

-- ============================================
-- 对话历史（可选，第一版主要在session_state中）
-- ============================================

CREATE TABLE IF NOT EXISTS chat_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    role TEXT NOT NULL,           -- "user" | "assistant"
    content TEXT NOT NULL,
    module TEXT,                  -- "faq" | "course" | "advisor" | "schedule"
    timestamp TEXT DEFAULT CURRENT_TIMESTAMP
);
```

### 5.2 侧边栏功能

- **模块切换**：Radio按钮，4个选项。切换不影响对话历史，但改变主Agent的路由偏好（用户可手动切换模式）
- **对话历史列表**：点击可回顾历史对话（session_state中存储）
- **清空对话按钮**
- **底部**：版本号、团队信息

### 5.3 对话区功能

- **消息流**：st.chat_message 组件
- **打字机效果**：使用 st.write_stream 模拟逐字输出（或至少显示加载状态）
- **时间戳**：每条消息底部显示时间
- **输入框**：st.chat_input，固定在底部

## 六、大模型调用方案

### 6.1 校内API配置

```python
# config.py
LLM_CONFIG = {
    "base_url": "https://llm.ustc.edu.cn/api/v1",  # 校内平台
    "api_key": "your-api-key-here",                  # 从平台获取
    "model": "deepseek-chat",                        # 推荐DeepSeek-V4，性价比高
    "temperature": 0.3,                              # Agent场景建议低温度
    "max_tokens": 2048,
    "timeout": 30                                    # 30秒超时
}

# Embedding配置
EMBEDDING_CONFIG = {
    "model_name": "shibing624/text2vec-base-chinese",  # 本地模型
    "device": "cpu"                                     # 本地运行
}
```

### 6.2 LLM客户端封装

```python
# utils/llm_client.py
from langchain_openai import ChatOpenAI

def create_llm():
    """创建LLM实例，对接校内平台"""
    return ChatOpenAI(
        base_url=LLM_CONFIG["base_url"],
        api_key=LLM_CONFIG["api_key"],
        model=LLM_CONFIG["model"],
        temperature=LLM_CONFIG["temperature"],
        max_tokens=LLM_CONFIG["max_tokens"],
        timeout=LLM_CONFIG["timeout"]
    )
```
