# 课表、校园工具与管理后台重构说明

> 状态：2026-09-01 已实现，等待本轮最终全量验证。
> 范围：本地开发仓库；不涉及服务器部署、课表编辑、Excel 导入或统计面板。

## 1. 前置开源调研

本轮没有找到一个能同时满足“科大真实个人课表、用户提交工具、管理员审核”的可直接移植项目。最终采用局部成熟组件与现有架构组合，第三方项目只学习交互和数据模型，不复制其业务代码。

| 方向 | 方案 | 优点 | 局限与结论 |
|---|---|---|---|
| 课表 | [FullCalendar](https://github.com/fullcalendar/fullcalendar) Standard TimeGrid（MIT） | React 适配成熟；支持真实起止时间、周视图、重叠事件、当前时间线、日期导航与自定义事件内容 | 默认视觉需定制，命名课段不是原生语义；选用 `6.1.21` Standard 包，不引入 Premium Scheduler |
| 课表备选 | [Schedule-X](https://github.com/schedule-x/schedule-x)、[React Big Calendar](https://github.com/jquense/react-big-calendar)（MIT） | 都支持周视图与时间槽 | 前者生态较小且默认移动策略不贴近样例；后者精确视觉和非均匀课节定制成本更高；未选用 |
| 排课领域参考 | [UniTime](https://github.com/UniTime/unitime)（Apache-2.0） | 大学课程、教室、周次和冲突模型成熟 | Java 大型排课系统，与当前 FastAPI/React 栈不匹配，只学习领域拆分 |
| 工具宫格 | [Homer](https://github.com/bastienwirtz/homer)、[Homarr](https://github.com/homarr-labs/homarr)（Apache-2.0） | 服务卡片层级、分组、搜索和快捷入口成熟 | Homer 是静态 YAML；Homarr 是完整平台且依赖过重；只学习卡片信息层级，复用现有 React/Radix/CSS |
| 工具宫格备选 | [Homepage](https://github.com/gethomepage/homepage)（GPL-3.0） | 响应式服务目录成熟 | 无申请审核，且 GPL 代码不复制进当前项目 |
| 管理后台 | [React-admin](https://github.com/marmelab/react-admin)、[Refine](https://github.com/refinedev/refine)（MIT） | 资源型 CRUD、筛选、认证抽象成熟 | 当前只有两类审核资源，引入第二套路由、数据层和视觉体系成本过高；继续使用现有 React/Radix/CSS |
| 列表备选 | [TanStack Table](https://github.com/TanStack/table)（MIT） | 后续复杂分页、排序和列管理可按需采用 | 当前搜索、状态筛选与队列/详情布局不需要额外依赖 |

最终选择的原因：FullCalendar 只承担已经成熟且容易出错的连续时间布局；课程事实、审核状态机、权限与持久化继续由本项目后端负责。这样既不手写日历定位算法，也不为一个审核队列引入整套后台框架。

## 2. 已确认范围

### 2.1 课表

- 使用官方 1–13 小节时间映射，同时标注第一至第四常用大课段和晚间时段。
- 周一至周日七列；支持前周、本周、后周和当前时间线。
- 多段排课、单双周、不连续周和显式时钟统一结构化；课程按真实起止时间定位。
- 重叠课程并排并警示；无法确认星期、周次或时间的记录进入“待确认”。
- 点击课程打开详情，只保留一个“问问小蜗”。
- 本轮不做课程颜色语义、类型图标、同步、编辑、全学期列表或“全”按钮。

### 2.2 校园工具

- 位于“校园服务”的第三个主视图，内部为“全部工具 / 我的申请”。
- 匿名可浏览；Demo/CAS 用户可提交名称、公开 HTTPS URL、受控分类和可选说明。
- 用户暂不选择图标；卡片显示名称、说明、分类、域名和“管理员审核”。
- 通过后在当前 namespace 面向全校展示；申请历史、驳回/下架原因、站内通知与重新申请均保留。

### 2.3 管理后台

- 独立 `/admin` 壳，默认工具审核；知识审核位于 `/admin/knowledge`；旧 `/review` 自动重定向。
- 复用现有管理员 RBAC、session、CSRF、Origin 校验和 Demo/Production 隔离。
- 工具审核支持关键词搜索、待审核/已通过/已驳回筛选、批准、强制原因驳回、下架和审计。
- 写操作使用 `expected_version` 乐观锁与 `X-Request-ID` 幂等；请求编号不能跨审核对象复用。
- 本轮不做课表后台、Excel 导入和统计面板。

## 3. 数据真实性

CAS 身份的课表只从当前 principal 对应的 jw 会话拉取。实时成功后同步结构化 `meetings` 到 SQLite；失败时才读取同一学生的缓存，并明确标记“本地缓存，仅供参考”。Demo fixture 是遵循真实节次规则的合成课表，持续标注演示数据，不读取或提交真实学生信息。

`GET /api/v1/academic/schedule` 输出课程基础字段，以及每段 meeting 的 `weekday / week_numbers / periods / period_label / start_time / end_time / location`。后端还输出学期起始日、总周数与当前教学周。前端不从课程名猜类型，不从残缺自由文本猜日期或地点。

## 4. 工具申请数据流

```text
匿名或登录用户读取目录
        |
        +-- production（anonymous / CAS）
        +-- demo（Demo 身份）

Demo/CAS 提交
  -> 服务端绑定申请人身份
  -> URL 安全校验与规范化
  -> campus_tool_applications(pending)
  -> 管理员 /admin 搜索、筛选并审核
       -> approved: campus_tools(active) + 审计 + 站内通知
       -> rejected: 强制原因 + 审计 + 站内通知
  -> active 工具进入当前 namespace 的全校目录
  -> 后续可下架并通知申请人，历史记录不删除
```

四张领域表位于审核 SQLite：`campus_tool_applications`、`campus_tools`、`campus_tool_audit`、`user_notifications`。官方 `config/links.yaml` 继续作为已核实官方入口的独立信任边界，社区工具不会写入该文件，也不会注册为 `eco:` Agent 工具。

## 5. 安全与隔离

- namespace 只能由服务端 principal 推导，客户端不能指定。
- anonymous 不可提交；Demo 只能写 demo；CAS 管理员只能按生产配置访问 production。
- 工具 URL 只接受公开 HTTPS，阻断 userinfo、敏感凭证参数、回环、私网和云元数据地址。
- 管理写操作同时要求登录、管理员权限、CSRF 与可信 Origin。
- 批准、驳回、下架、通知与审计在 SQLite 事务中完成；版本冲突返回 409，前端提示刷新。
- 卡片标注“社区提交 · 管理员审核”，不得标为官方来源。
