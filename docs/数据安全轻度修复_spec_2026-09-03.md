# 数据安全轻度修复 Spec（2026-09-03）

> 契约（grill-requirements 六维确认）。范围：P1 reset 加固（方案甲）/ P7 每日备份（全 7 项）/ P6+P8 监控探针 / B3+B4 恢复增强与 SOP。
> **核心问答链路（P3 搜索源接入、P5 LLM 优化、P4 微信管线代码）本次一律不动。**

## 1. Goal
让"数据被误删/被清空/被恶化"这类事故：① 外部无法触发（reset 默认禁用）；② 发生了也能 24h 内还原（每日备份）；③ 发生了会有人知道（探针+哨兵）；④ 恢复路径文档化。

## 2. Boundary
**可改**：
- `xiaowo_web/settings.py`（加 `XIAOWO_DEMO_RESET_ENABLED`，默认 false）
- `xiaowo_web/api/routers/auth.py`（reset 端点：开关 404 / 密钥校验 / 预导出 / 审计）
- `frontend/src/App.tsx` + `components/AppShell.tsx` + `AccountMenu`（重置项：未启用不渲染；启用时需输入"重置"确认）
- `.env.example`、`deploy/server/start_all.sh`（接入备份循环）
- 新增：`deploy/server/backup_daily.sh`、`deploy/server/sentinel.py`（探针哨兵，或并入 watchdog 的独立脚本）
- `xiaowo_web/api/routers/health.py`（ready 增加 approved_index/search_quality 两项）
- 恢复脚本 `deploy/server/restore_review_data.py`（防呆提示）
- `docs/部署规格与记录_2026-09-01.md`（事故 SOP 节）

**不得改**：`agents/qa/*`、`xiaowo_web/evidence/*`（pipeline/wechat/rewrite/clients/gate）、`chat/runner.py`、`chat/manager.py`、`knowledge/*`、`config/links.yaml`。

## 3. Acceptance criteria（命令可验证）
- **P1**：
  - 默认（未设 `XIAOWO_DEMO_RESET_ENABLED=true`）：`POST /api/v1/auth/demo/reset` → **404**；前端账户菜单无"重置"项。
  - 开启后：缺/错 `X-Demo-Reset-Key` → **403** + 审计行；正确密钥+确认 → 200，且**先导出** `data/backups/demo_reset_<ts>/` 成功才清空；清空后有种子被 re-seed。
  - 前端开启场景下需输入"重置"字样确认。
- **P7**：`backup_daily.sh --once` 产出 7 项（review.db/xiaowo.db/course_data.db 用 SQLite .backup；web_evidence/chroma/programs_jw/deploy 用 tar；.env 单独 600 权限）到 `data/backups/daily/<date>/`；保留 7 日 + 周备份 5 份；循环接入 start_all/stop_all；`--once` 幂等可重复跑。
- **P6/P8**：`/api/v1/health/ready` 返回 checks 含 `approved_index`（active 指针存在且 manifest/bm25 可读）与 `search_quality`（哨兵 60s TTL 缓存；≥1 结果为 true；连续 2 次失败为 false）；哨兵 loop 每 5 分钟一次搜索+索引检查，状态写 `deploy/server/run/sentinel_state.json`。
- **B3/B4**：restore 脚本在产物缺失时明确提示"请从 data/backups 还原"；部署文档增补"数据事故恢复 SOP"（含 2026-09-03 实操回放）。
- 回归：`pytest tests/web -q` 全绿；前端 `npm run build` 通过；服务重启后以上全部生效。

## 4. Failure modes
| 场景 | 正确行为 |
|---|---|
| reset 预导出失败 | 中止清空（421/500），数据不动 |
| 密钥错误 | 403 + 审计行（含来源 IP） |
| 备份中途失败（磁盘满/库锁定） | 当日目录标记 `failed`，保留上次成功备份，不阻塞服务 |
| 哨兵搜索抖动 | 连续 2 次失败才算 false（防抖）；ready 永远不因此 503 杀服务 |
| 恢复产物缺失 | 脚本提示使用备份还原并给出命令 |

## 5. Priorities
安全性 > 完成度；核心链路不动优先级最高（冲突时砍本轮的监控/文档）；一切改动最小化、可回滚（改前 git 快照）。

## 6. Non-goals
搜索引擎接入（Serper/Brave/官方直采）；LLM 缓存/瘦身/备用端点；WechatClient/pipeline 微信分支改造；公众号独立采集脚本（本轮不做）；问答链路任何行为/预算/降级改动；UI 重构。
