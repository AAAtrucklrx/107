# Xiaowo Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a tested Capacitor Android client reusing React and authenticated Xiaowo APIs.

**Architecture:** Separate native school-login WebView, allowlisted CapacitorCookies adapter, Keystore encrypted bearer storage, PKCE one-time exchange and server encrypted school sessions. Web cookie authentication remains intact.

**Tech Stack:** Capacitor 7.6.9 (security-patched), Java21/Android35, existing React/TypeScript/Vite and FastAPI/SQLite/AES-GCM.

**Spec:** `docs/superpowers/specs/2026-10-24-mobile-design.md`

## Global Constraints

- APK ≤25MB; no Python/models/databases in app.
- No passwords or plaintext school cookies in app-written files or logs. User explicitly accepts system WebView temporary persistence with cleanup.
- Debug loopback HTTP only; release HTTPS only. No live server changes. No Git commits or secrets committed.
- Preserve existing worktree changes and all QA/tool business decisions.
- Exact native and HTTP interfaces are in the design spec; coordinate deviations before editing peer files.

## Review Focus

- Cancellation or timeout followed by a late login response must not silently authenticate.
- Two simultaneous students must not share requests.Session or principal data.
- Invalid bearer plus valid browser cookie must fail closed.
- Offline logout must clear device data and report unconfirmed server revocation honestly.
- Wrong WebView host, TLS error or deep link must never expose bridge/token.
