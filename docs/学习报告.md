## 1. 项目概述

**小蜗（🐌）** 是面向中国科学技术大学师生的校园智能助手，为 **107 杯比赛项目**。当前版本 **v2.1（QA LangGraph v3.0）**。

核心能力四大模块 + 两个扩展页面：

| 模块 | 能力 |
|------|------|
| 📚 智能问答 | 80 篇校园知识库文档（769 条向量分块）的 RAG 问答（办事/教务/生活/就业/科研与升学），回答可附官方来源网址 |
| 📊 课业助手 | 成绩查询、课表查询、GPA 计算、考试安排、空教室查询；CAS 登录后经 jw API 拉取真实教务数据 |
| 🔍 选课顾问 | 基于 icourse.club 真实评课（5667 个课程页 / 44418 条评论，不合并同课多师）推荐：真实均分降序、同课多师对比、评论原文引用、按培养方案必修/选修分组 |
| 📅 日程管理 | 日程增删查、冲突检测、课表导入、空闲时间匹配 |
| 🎓 培养方案 | 方案总览 / 学期规划 / 培养进度三合一页面（`ui/program_page.py`） |
| 🎪 活动推荐 | 校团委 young 平台活动 + 课表空闲 MMR 推荐（每天最多一次弹窗） |

**入口文件**：
- `app.py` — 正式版（CAS 真实登录）
- `app_test.py` — 测试版（模拟登录 + 注入 `%TEMP%\xiaowo_personal\data.json` 个人数据备份，绕过 CAS）

**核心设计原则**（贯穿全项目）：所有降级/模拟数据均带**来源标识**（实时数据 / 本地缓存 / 模拟数据），保证结果可追溯。

### 2.2 一次问答的完整生命周期

1. **UI 层**：`app.py::process_query` 从 `st.session_state` 取用户画像与最近 20 条对话历史，调用 `agents.qa.graph.run_qa(query, module_signal, student_id, user_profile, chat_history)`
2. **embedding_parse**（节点1）：双通道并行 —— ① `knowledge.intent_classifier.classify()` 做 12 类意图分类（embedding 相似度为主、关键词兜底）；② `FAQVectorStore.search()` 混合检索召回知识库候选（向量 + BM25 + RRF 融合，top_k=12；2026-08-16 起 5→8→12 提升多义字段/组合问法召回）
3. **think**（节点2）：LLM 决策引擎（temperature=0），四选一：`clarify`（追问）/ `retrieve`（改写检索词重检索）/ `call_tool`（调工具）/ `compose`（合成）。含 16 条决策规则；敏感词、闲聊、个人信息问答走确定性快速通道不调 LLM；LLM 失败降级 `_think_fallback` 确定性规则
4. **act**（节点3）：按决策执行 —— retrieve 则重检索并去重合并候选；call_tool 则查工具注册表执行，**act 层兜底注入** `student_id`/专业/年级/已修课程/个人方案树，结果回填 `tool_results`
5. **循环**：act → think 循环最多 **4 轮**（MAX_ROUNDS），think 输出 compose/clarify 或超轮次即跳出
6. **compose**（节点4）：LLM 综合回答（temperature=0.3），引用标注来源；敏感拒绝/闲聊/个人信息走模板；`_strip_rule_prefix` 剥离规则续写与脏前缀；LLM 失败降级 `_fallback_answer` 格式化已有结果
7. **回 UI**：`add_assistant_message` 写入 `st.session_state.messages`

## 4. 关键模块详解

### 4.1 agents/qa/ —— v3 统一 QA LangGraph（核心）

| 文件 | 职责 |
|---|---|
| `graph.py`（147 行） | 图装配（START→embedding_parse→think→条件路由→act→compose→END）、`_route_after_think` 路由规则（compose/clarify/超4轮→结束，否则→act）、模块级编译缓存、`run_qa` 统一入口（含异常兜底返回结构） |
| `state.py`（29 行） | `QaState` TypedDict：query/intent/intent_top3/candidates/student_id/user_profile/chat_history/decision/retrieve_query/tool_calls/tool_results/rounds/thought_log/clarify_question/answer/error |
| `intents.py`（98 行） | 12 类意图定义 + 每类 3-5 条示例 + `_TOOL_HINTS` 工具提示映射；意图仅是 think 的参考信号 |
| `nodes.py`（979 行） | 四节点全部实现，项目最大单文件，见下 |

**12 类意图**：知识问答、查成绩、查课表、查空教室、查考试、课程搜索、选课推荐、教师点评、日程查询、日程管理、闲聊、敏感拒绝。

**nodes.py 四节点**：

- `embedding_parse`：意图分类（分类置信度 <0.5 时才参考侧边栏模块信号）+ 知识库候选召回（失败仅告警不阻断）
- `think`：LLM 决策（16 条规则约束 JSON 输出），关键机制：
  - **快速通道**（不调 LLM）：敏感词→compose 拒绝；闲聊→compose 回应；个人信息问答（"我大几/我什么专业/我叫什么/我学号多少"）→模板回答，防止 LLM 编造
  - **防重复调用**：`done_tools` 集合拦截同工具二次调用（规则 15 的 clarify 后精确重试除外）
  - **宽松 JSON 解析** `_parse_json_loose`（容忍 ```json 代码块与前后缀）
  - **降级** `_think_fallback`：按意图走确定性计划（`_plan_advisor`/`_plan_course`/`_plan_schedule`/search_faq）
- `act`：retrieve 重检索（按 chunk id 去重合并）；call_tool 执行并做三层参数兜底：
  1. `_PERSONAL_TOOLS` 集合（13 个个人数据工具）强制注入 `student_id`
  2. `recommend_courses` → `_enrich_recommend_args`（专业/年级/已修课程/学年号）
  3. 培养方案工具 → `_enrich_program_args`（`get_program_progress` 才注入 `taken_courses`，避免 extra=forbid 校验失败；注入 CAS 个人方案树，per-student 进程缓存 + 归属校验）
- `compose`：综合回答；`_build_tool_summary` 按 9 类工具定制 dump 格式（成绩/课表 60 条、选课 80 条上限，推荐含必修/选修分组与选课季语义提示）；`_strip_rule_prefix` 三段式剥离开头规则续写（含 `smart_toy` 类脏前缀）；`_fallback_answer` LLM 不可用时格式化工具结果与候选

## 6. 代码规范与工程约定

### 6.1 编码风格

- 全项目中文 docstring + `# ── 分区 ──` 注释习惯；新代码用 `from __future__ import annotations` 与类型标注；`TypedDict` 定义图状态
- 模块私有函数 `_` 前缀；延迟导入防循环依赖（tools/services 均为函数内 import）
- 数据库连接用后即关（`_cdb()` 每次新建连接，避免坏连接缓存）

### 6.2 容错设计范式（项目精髓）

1. **三级降级**：实时（jw）→ 本地缓存（SQLite）→ 锁定提示，均带来源标识
2. **参数兜底在 act 层**：不信任 LLM 传参，身份类参数强制注入（学号/专业/年级/已修课程/方案树）
3. **LLM 决策全链路降级**：think 失败→确定性规则；compose 失败→格式化已有结果；JSON 宽松解析
4. **快速通道模板化**：敏感拒绝/闲聊/个人信息问答不依赖 LLM，防编造防注入
5. **防死循环**：轮次上限 4 + 工具防重复调用 + 超轮强制合成

### 6.3 Windows 环境约定（实测有效）

- 用 `py -3` 或完整解释器路径 `C:\Users\Richelieu\AppData\Local\Programs\Python\Python314\python.exe`（`python` 是 WindowsApps 占位符）
- PowerShell 无 `&&`，用 `;`；内联 `-c` 引号转义频繁失败——**写脚本文件后运行**（本次分析已复现该坑）
- Streamlit 修改 agent 代码后 Rerun 不生效，必须 `taskkill` 杀 8501 端口进程重启

### 6.4 测试方法论

- 无 pytest；自研 `t(name, ok, detail)` 断言模式（check_course_db/verify_tools/test_fixes 同构）
- 实测闭环：起测试实例 → Playwright 提问 → 抓回答文本与截图 → 比对白名单 → 改码 → 编译 → 重启 → 复测

### 6.5 Git 约定

- 提交统一由指挥中心执行，身份 `xiaowo-dev <xiaowo@local>`；提交信息中文、带类型前缀（feat/fix/docs/chore）
