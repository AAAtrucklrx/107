## 1. 项目概述

| 模块 | 能力 |
|---|---|
| 📚 智能问答 | 80 篇 md → 769 分块混合检索 RAG；附官方来源；断网 BM25-only 降级 |
| 📊 课业助手 | 成绩/GPA/课表(节次精确到分钟)/考试/空教室/课程搜索；jw API 真实数据 |

## 2. 架构

分层（表驱动）：表现层 `app.py/app_test.py + ui/{chat,program_page,links_page,activity_dialog}` → 智能体层 `agents/qa/{graph,nodes,intents,state}.py + tool_registry.py` → 工具层 28 内置 + `tools/ecosystem/` → 服务层 `services/{cas_client,service_container,session_ctx,young_client,activity_recommender,activity_profile}` → 数据层 `database/ + data/course_data.db + knowledge/chroma_db`。外部依赖：科大 LLM 平台 · CAS · jw 教务 · catalog 公共 API · young 青春科大 · icourse 评课。

### 2.1 一次问答生命周期

1. `app.py::process_query` 取画像+最近 20 条历史 → `run_qa(...)`（graph.py 入口，try/finally 复位会话上下文）。
2. `embedding_parse`：①`intent_classifier.classify()`（embedding 放行价 关键词兜底，置信度<0.5 才参考模块信号）；②`FAQVectorStore().search()` 混合检索 top_k=12（维度不匹配降级 BM25-only）。
3. `think`：LLM 决策 四选一（clarify/retrieve/call_tool/compose），规则 1-22；快速通道（敏感/闲聊/个人信息）+ 确定性路由先行；LLM 失败降级 `_think_fallback`。
4. `act`：retrieve 去重合并；call_tool 执行 + **三层参数兜底**（个人工具补 student_id、recommend_courses 补画像/已修/GPA、add_event 时间 ISO 校验重解析、培养方案工具补已修/方案树）。
5. 循环 ≤4 轮（MAX_ROUNDS）；compose/clarify/超轮出台跳出。
6. `compose`：LLM 综合回答（temperature=0.3）+来源标注+官方 URL；失败降级 `_llm_down_answer`（熔断提示+摘要直出）。
7. 回 UI `add_assistant_message`。

## 4. 深潜四链路（工程实测）

### 4.1 agents/qa/ —— 统一 QA 状态机（核心）

| 文件 | 行数 | 职责 |
|---|---|---|
| graph.py | 152 | 图装配 + `_route_after_think` 路由 + 模块级编译缓存 + `run_qa` 入口（try/finally 复位 session_ctx） |
| state.py | 29 | `QaState` TypedDict（含 **llm_down**/candidates_found 等） |
| intents.py | 134 | 15 类意图 + `_TOOL_HINTS`；意图仅参考信号 |
| nodes.py | 1500 | 四节点全部实现 + 规则 + 摘要构建（项目最大单文件） |

**nodes.py 关键机制**：
- `embedding_parse`：意图分类（弱信号）+ 候选 top_k=12，失败仅告警。
- `think`：快速通道（敏感/闲聊/`_is_personal_qa` 个人信息模板）；确定性路由 `_teacher_course_route`（→analyze_teacher）/`_direct_tool_route`（→check_course_conflict/evaluate_selection_pressure）/`_is_dayview_query`（→query_daily_schedule）；`done_tools`+`_check_tool_choice` 防重复；`_parse_json_loose` 宽松 JSON；`_think_fallback`+`_keyword_intent_fix` 降级；失败 `mark_llm_down_if_unreachable` + 置 `llm_down`。
- `act`：retrieve 去重；call_tool 执行 + 三层参数兜底；未知工具兜底报错。
- `compose`：LLM 综合；`_build_tool_summary` 9 类定制 dump（成绩 60/课表 80 上限、选课必修选修分组+`_term_zh`、教师防截断、活动逐条、render_link 话术、eco: 署名）；`_strip_rule_prefix` 四模式剥离；`_llm_down_answer` 熔断降级。

**THINK 规则 1-22**（要点）：1-9 决策与防重复；10 选课软过滤；11/13 教师+课程双参数；12 工具失败重试一次；14 ambiguity→clarify 反问（禁替用户选）；15 澄清后精确重试例外；16 个人工具须带 student_id 且日期解析；17 冲突/退补选映射；18 复合问题每轮一工具；19 联系人事务须学院名补检索；20 生态工具署名仅供参考；21 强操作只能给 render_link/知识库 URL，禁拼造；22 活动问句→query_activities。

**深潜观察**：15 个个人工具在 `_PERSONAL_TOOLS`，act 强制注入学号；`_REGISTRY_CACHE`/`_valid_tools()` 懒加载校验 LLM 选择；intents 头注释"14 类"漂移；nodes.py 单文件 1500 行，容错范式完备但可读性有代价。

### 4.2 services/llm_client.py —— LLM 熔断（深潜）

| 项 | 值 |
|---|---|
| 熔断窗 | `_LLM_DOWN_WINDOW=600s` 进程级 `_LLM_DOWN_UNTIL` |
| 开窗条件 | `mark_llm_down_if_unreachable`：仅连接级（ConnectionError/connect/LLMUnavailableError）；读超时(平台慢/限流)**不动窗** |
| 快速失败 | `create_llm` 窗内抛 `LLMUnavailableError`，max_retries=1(默认)，timeout=`httpx.Timeout(30, connect=5)` |
| 设计取舍 | 连接级失败开窗 600s（"熔断不传染"指读超时不传染）；❌ 但也意味着单请求连接失败殃及进程内**所有**用户降级 10 分钟 |

**深潜观察（审查项）**：进程级全局熔断，多用户并发下 A 用户断网连累 B 用户降级；窗口 600s 偏宽（建议 60-300s 或按会话隔离）。列为低优架构观察，待办审计已记录。

## 6. 容错设计范式（项目精髓）

1. **三级降级**：实时 jw → 本地缓存 SQLite → locked/提示，均带来源标识。
2. **act 层参数兜底**：不信任 LLM 传参，身份类参数强制注入（学号/专业/年级/已修/方案树/GPA/活动学号）。
3. **LLM 全链路降级**：think 失败→确定性规则；compose 失败→摘要直出；JSON 宽松解析；**LLM 熔断窗**（连接级才开）。
4. **快速通道模板化**：敏感/闲聊/个人信息问答不依赖 LLM，防编造防注入。
5. **防死循环**：轮次上限 4 + 防重复工具调用 + 超轮强制合成。
6. **防幻觉增强**：compose 提示词 9 类防透气规范（不编数据/不篡改工具结果/严格顺序/数值以官方为准/特例不得代表整体）。
