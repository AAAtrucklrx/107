# 小蜗前端 UI 重构规格

> 状态：已批准，已实现
> 日期：2026-08-30
> 范围：React Web vNext 三个用户工作区与独立管理后台
> 实施路径：code-first
> 视觉方向：冷色数字编目台
> 方向种子：`fe17c534`

## 1. 目标

把现有“小蜗 · 科大学术工作台”从可用的功能集合重构为安静、精确、可信、适合高频使用的完整产品界面。重构必须同时改善视觉辨识度、任务效率、响应式布局、可访问性和状态表达，不改变已经确认的业务契约。

成功交付必须满足以下结果：

1. 问小蜗、我的学业、校园服务使用同一套清晰且可复用的用户端视觉系统；知识审核与工具审核进入视觉明确区分的独立管理后台。
2. 1440px 桌面、768-1199px 平板、390px 手机和 320px 最小宽度均不存在重叠、裁切或不可达操作。
3. 默认浅色与完整深色主题保持同等层级、对比度和品牌识别。
4. 所有身份、来源、演示、缓存、联网、证据、冲突和审核状态均以文字、图标和结构共同表达。
5. 高频操作可被快速扫描，触控目标、键盘顺序、焦点和屏幕阅读器行为达到 WCAG 2.2 AA。
6. 原有测试、远端新增学业能力、审核 hardening 和聊天输入区修复全部保留。

## 2. 范围与非目标

### 2.1 范围

- `frontend/` 内 React、TypeScript、CSS、主题、图标、组件和测试。
- 用户端稳定路径：`/`、`/academic`、`/campus`；管理端稳定路径：`/admin`、`/admin/knowledge`，旧 `/review` 重定向到后者。
- 用户应用壳、独立管理壳、导航、账户菜单、品牌字标呈现、聊天、来源、学业、校园入口、校园工具与两类审核。
- 加载、空、错误、禁用、降级、断流、删除确认、异步处理和权限不足状态。
- 浅色、深色、桌面、平板、手机、减少动态效果和键盘流程。
- 与 UI 可靠性直接相关的轻量逻辑修正，例如局部请求失败隔离、合理自动滚动和动态主题色。

### 2.2 非目标

- 不改后端 API 路径、字段含义、认证模式、权限判断或数据保存期限。
- 不重新引入推荐侧排课偏好、`schedule_constraints`、`force_calls` 或课程三联动。
- 不修改 Streamlit 迁移期回退界面。
- 不更换“小蜗”字标图形，不使用官方校徽，不设计卡通吉祥物。
- 不虚构校园摄影、用户评价、使用指标、联网可用性或正式 CAS 状态。
- 不引入新的大型组件库、图表库、3D、WebGL、滚动劫持或装饰性动画。

## 3. 不可回归产品契约

### 3.1 身份与权限

- 匿名用户仅使用公共能力，历史只保存在当前浏览器，登录后不自动合并。
- Demo 登录、退出、恢复演示数据、CAS 入口和主题持久化继续可用。
- 学业和审核导航继续由能力控制；无权限时返回聊天工作区。
- Demo 身份必须持续显示 `PB25111691`、专业、年级和“演示数据”。
- 专业、年级和培养方案只来自当前认证用户档案，不猜测、不跨用户继承。

### 3.2 问答与证据

- SSE 的检索本地、联网搜索、抓取页面、核验证据和组织回答阶段继续显示。
- 正文只在证据阶段完成后流式输出，不显示思维链，不先给未经核实的结论。
- 保留停止、断流重连、按原模式重试、复制、反馈和来源展开。
- 保留 `[1]` 行内引用、机构/域名、发布时间、抓取时间、来源等级与失效状态。
- 证据不足和来源冲突必须明确说明；联网不可用不得伪装成功。

### 3.3 学业与推荐

- 保留成绩按学期分组、培养方案按建议学期分组、GPA、课表与来源标识。
- 每门课程只保留一个“问问小蜗”。
- 课表按周一至周日和真实时钟展示，保留 1–13 小节、周次、起止时间、地点与多段排课；支持前周/本周/后周、当前时间线、重叠警示、课程详情和待确认数据。
- 课程范围是硬条件；兴趣、工作量、教师和目标学期默认是软排序，只有“只要/必须”升级为硬过滤。
- “推荐且不冲突”只推荐并说明未检查课表；独立冲突检查保留。
- 个人方案失败时只显示已验证身份对应的专业通用参考，并明确不是个人培养方案。

### 3.4 审核与发布

- 管理后台与普通用户界面完全分离；仅管理员能力可进入。`/admin` 默认工具审核，知识审核位于 `/admin/knowledge`。
- 工具审核支持搜索、申请状态筛选、批准并上架、强制原因驳回、下架与审计；所有写操作继续使用 CSRF、服务端命名空间与乐观锁。
- 保留逐块 `pending / approved / rejected` 三态、至少批准一块、TTL、复抓、来源治理、发布 generation 和回滚。
- 保留 demo 与 production 审核隔离，HTTP production 不开启个人区或管理区。
- 不弱化原文、清洗稿、差异、分块和实际批准版本之间的关系。

## 4. 视觉方向决策

### 4.1 设计判断

这是高频操作型学术工作台，不是营销页。用户通常在宿舍、图书馆、教室或实验室的普通屏幕上快速核实信息、查看进度或完成操作。默认采用浅色冷白工作面，深色主题服务夜间使用。

设计参数：

- `DESIGN_VARIANCE: 6`：结构有辨识度，但不牺牲熟悉的操作位置。
- `MOTION_INTENSITY: 4`：只用于状态反馈、工作区切换和层级变化。
- `VISUAL_DENSITY: 7`：保留学业与审核所需密度，通过分组和留白控制负担。

### 4.2 独特机制与拒绝的默认答案

独特机制：小蜗把个人学业任务与可核验证据放在同一工作台，并用来源门槛决定何时联网、何时输出确定结论。

拒绝两种常见答案：

- 不做 ChatGPT 式居中聊天页加通用左侧栏。
- 不做海报式、实验性校园门户，让表达压过任务。

### 4.3 七个本土化候选

1. 科研仪器工作台：以数据采集终端、状态读数和固定操作区组织高频任务。
2. 学术论文边注：以正文、引文、来源边栏和批注层级表达证据关系。
3. 冷色数字编目台：以现代图书馆目录、检索终端和索引记录组织三个用户工作区；后台沿用结构语言但使用独立壳。
4. 学期规划总账：以学期、课程、学分和计划矩阵组织进度。
5. 校园导视系统：以区域、方向和清晰标识组织导航。
6. 数字实验记录簿：以时间、事件、观察和结论组织会话与审核。
7. 科学坐标与谱线：以数据图形、坐标和状态轨迹表达检索与进度。

方向抽签指定第 3 项，且它能够同时承载聊天、学业、校园入口和高密度审核，因此不重抽。

### 4.4 外部挑战方向评估

| 挑战方向 | 结论 | 原因 | 被保留的纪律 |
|---|---|---|---|
| 法式流行唱片封套 | declined | 识别鲜明但无法承载高密度学业和可信状态 | 每个工作区只建立一个主视觉场，不堆同权卡片 |
| 精确主义工业平面 | competitive | 结构诚实、层级强，但工业感弱化校园与学术身份 | 用平面分区和硬层级替代装饰边框 |
| 阴极数字与金属网 | declined | 暗色发光与默认浅色、蓝青品牌和可读性冲突 | 所有可选状态保留明确前后关系，不让状态消失 |
| 电影剪辑台轨道 | competitive | 能表达处理进度，但黑橙语法与科大品牌冲突 | 检索和发布流程使用稳定、可回看的阶段记录 |
| 抽绳变形披风 | declined | 响应式隐喻有价值，服装材料与产品无关 | 移动端采用明确重排模式，不压缩桌面布局 |
| 字母风暴 | declined | 语义动画过强，会干扰任务和屏幕阅读器 | 动效必须由状态触发且结果可逆、可描述 |

### 4.5 最终视觉世界

“冷色数字编目台”不是复古纸卡，也不是拟物图书馆。它是一套现代、冷静的机构级检索界面：

- 结构来自索引、目录记录、来源边注、学期分组和可追溯状态。
- 大区域以背景层级和留白划分，边框只用于真实容器或数据边界。
- 条目优先使用行、带、分组和侧栏；卡片只用于重复对象、对话框和确需框定的工具。
- 品牌蓝只承担主操作和当前工作区；青色只承担联网、检索和证据活动。
- 视觉记忆点是“索引脊”：桌面左侧导航与内容标题共享一条稳定的编号/标题基线，移动端转化为紧凑标题带。
- 签名交互是“证据抽屉”：来源、限制和证据状态从回答右侧或底部按需展开，不移动正文阅读起点。

状态色独立于主色：成功、警告、错误、冲突和过期分别使用语义色，所有状态必须带图标与文字。禁止用低对比彩色文字放在同色浅背景上。

### 5.2 字体与数字

- 主字体使用 Noto Sans SC Variable 与系统中文无衬线回退，不使用衬线体承担产品 UI。
- 数字、学号、时间、学分和技术元数据使用 `ui-monospace` 回退栈，但不把整页做成终端风格。
- 正文最小 14px；辅助信息最小 12px；移动端输入和正文不低于 16px，避免浏览器缩放。
- 标题依靠字重、间距和结构建立层级，不使用超大字号或负字距。
- 全局 `letter-spacing: 0`；仅真实代码或表格数字允许等宽数字特性。

### 5.3 形状、边框和阴影

- 输入与紧凑控件半径 4px；按钮与面板 6px；对话框 8px。
- 分段模式控件可以使用连续轨道，但不把普通文字命令做成药丸。
- 阴影仅用于对话框、浮层和固定输入区，使用冷灰蓝透明阴影，不使用纯黑重阴影。
- 禁止卡片套卡片。页级区域不悬浮，重复条目才使用独立容器。

### 5.4 尺寸与密度

- 桌面交互控件默认最小高度 40px；触控或窄屏最小 44px。
- 图标按钮固定 40x40px，移动端 44x44px。
- 主内容最大宽度 1680px；阅读正文单行控制在约 76 个中文字符以内。
- 桌面数据区可以紧凑，但不得出现 8-11px 文本。
- 表格数字右对齐，标题左对齐，状态列固定，动态内容不能推动整体布局跳动。

## 6. 响应式架构

### 6.1 桌面，`>= 1200px`

- 左侧 216px 索引脊，包含字标、环境、三个主要工作区和账户入口。
- 聊天区使用 260px 历史索引 + 主对话；来源在回答内部按需展开，不常驻占宽。
- 学业区以全宽分组和双列摘要组织，课表和长表拥有稳定滚动容器。
- 审核区采用条目索引、审核正文和元数据侧栏的三段式工作面。

### 6.2 平板，`768-1199px`

- 导航缩为 72px 图标轨道，标签通过 tooltip 和当前页标题补足。
- 聊天历史、审核条目索引改为可打开的侧边 sheet，不挤压正文。
- 学业摘要降为单列或二列自适应；任何固定宽表格必须有明确滚动边界。
- 输入区始终保留独立网格行，不能被消息内容挤出视口。

### 6.3 手机，`< 768px`

- 顶部 56px 品牌与账户栏，底部动态列数工作区导航；匿名只有两个入口时只渲染两列。
- 页面使用 `100dvh` 与安全区内边距，不使用 `100vh`。
- 聊天历史、来源、审核索引和筛选使用 sheet 或折叠区。
- 学业和审核数据优先重排为有标签的行组；只有课表等二维关系保留横向滚动。
- 作曲器和主操作位于拇指可达区域，键盘弹出后仍保持可见。

### 6.4 最小宽度，`320-389px`

- 隐藏非必要说明，不隐藏状态和来源。
- 最长中文按钮允许合理换行，但主命令优先缩短文案并保持触控高度。
- 不出现水平页面滚动；局部二维数据滚动必须被容器约束。

## 7. 工作区规格

### 7.1 应用壳

- 字标使用现有 SVG 作为 mask，使浅深主题颜色可控且不修改图形。
- 导航使用同一图标家族和统一线宽，当前页同时通过背景、左侧索引标记和 `aria-current` 表达。
- 环境标识位于品牌下方，生产环境不显示；演示状态在内容顶部持续可见。
- 账户菜单保留身份、主题、审核入口、演示恢复、登录和退出；危险命令与普通命令分组。
- `theme-color` 随主题同步更新。

### 7.2 问小蜗

- 空会话显示 6 个方块化常见问题：匿名或个人学业能力不可用时使用公共校园问题；登录且具备个人学业能力时使用今日课表、成绩与 GPA、培养方案进度、下学期推荐、独立冲突检查和本周日程。
- 常见问题使用桌面 3×2、平板 2×3、手机单列；每块只显示短标题和说明，点击仅填入完整问题并聚焦输入框，不自动发送。
- 从学业页带入问题时隐藏启动方块；只有新建会话恢复。能力不可用时用公共问题补足，不显示无效个人入口。
- 历史是索引列表，当前会话、日期和删除操作稳定对齐。
- 删除单条与清空全部必须经过确认；移动端删除操作始终可见。
- 检索范围使用具有 `radiogroup/radio` 语义的分段控制，联网禁用时给出文本原因。
- 阶段条是唯一实时播报区；流式正文不嵌套 `aria-live`，完成时单独播报。
- 仅当用户仍接近底部时自动滚动；用户向上阅读后显示“回到最新”命令。
- 作曲器是独立固定网格行，发送、停止、范围和字数状态不改变整体高度。
- 回答操作、限制与来源采用低干扰工具条；来源通过证据抽屉展开。

### 7.3 我的学业

- 页头显示当前身份、专业、年级、档案来源和培养方案来源。
- GPA、已修学分、课程数等摘要使用一条分隔式数据带，不使用嵌套统计卡。
- 成绩、课表、培养方案和进度按任务分区，并保留学期分组。
- 四类数据独立加载和失败；一个接口失败不能清空其余成功内容。
- 空状态说明具体缺失的数据与来源，不猜测结论。
- 课程行只保留“问问小蜗”，并在窄屏保持课程名、学分、属性和操作可读。

### 7.4 校园服务

- 首屏由 8 个精选启动方块和完整分类目录组成；精选入口只取 `config/links.yaml` 的 `featured/priority`，前端不得复制 URL。
- 服务方块使用桌面 4 列、平板 3 列、手机 2 列，保持近方形稳定尺寸、6px 以内圆角和 1px 结构线；整块打开外链，域名与“配置审核”状态始终可见。
- 其余入口按真实类别分组；桌面和平板全部展开，手机默认只展开“教务学习”，搜索或分类筛选时展开匹配类别。
- 服务与活动保留独立搜索和筛选状态。服务搜索时隐藏精选区，只显示去重结果；活动继续使用时间列表，不方块化。
- 搜索和分类筛选有明确结果数、稳定骨架、空结果与清除筛选操作。
- 官方性和来源通过文字标签表达，未知域名不获得最高可信等级。
- “校园工具”作为第三个主视图，与官方入口分开；卡片显示工具名称、可选说明、分类、域名与“管理员审核”，整块打开外链，用户暂不选择图标。
- 匿名用户可浏览；Demo/CAS 用户可提交名称、公开 HTTPS 链接、受控分类和可选说明，并在“我的申请”查看状态、原因、历史与站内通知。

### 7.5 管理后台与知识审核

- 管理后台使用独立深色侧栏、环境标识和 Demo/Production 空间提示，不复用用户端底部导航。
- 工具申请在手机上使用“队列 → 全宽详情 → 返回队列”的单面板流程，操作按钮不得挤压申请信息。
- 桌面将条目索引、内容审核、来源与发布信息组织为连续治理工作面。
- 现有自制 tabs 改用 Radix Tabs，支持方向键、Home/End 和正确 ARIA。
- 分块决定使用 `radiogroup/radio` 或等价语义，三态均有文字、图标和计数。
- “至少批准一块”在提交前就地提示；错误聚焦到对应分块或总览。
- 原文、清洗稿和 diff 保持可比；移动端用标签页或分段切换，不横向压成三列。
- TTL、失效、复抓、generation 和回滚状态使用一致的状态行与确认对话框。

## 8. 共享组件

在现有组件边界上补齐以下可复用原语：

- `WorkspaceHeader`：工作区标题、说明、状态与主要命令。
- `StatusBadge`：文字、图标、语义色和可选时间。
- `SegmentedControl`：模式选择，支持 radio 语义和键盘操作。
- `IconButton`：固定尺寸、tooltip、可见焦点和禁用原因。
- `ConfirmDialog`：单条删除、清空、回滚等不可逆或高风险操作。
- `EmptyState`、`ErrorState`、`SkeletonRows`：与最终布局同形的状态组件。
- `DataBand`：分隔式学业指标，不产生卡片嵌套。
- `ResponsiveDataList`：桌面表格、移动标签行组的同一数据来源。
- `Sheet`：平板和移动的历史、来源、索引与筛选。
- `EvidenceDrawer`：回答来源、限制和证据元数据。
- `LaunchTile`：配置驱动的官方服务外链方块，始终显示域名和审核状态。
- `StarterPromptTile`：只填充聊天输入框的常见任务方块，不共享外链语义。

共享组件不得吞掉业务状态，也不得用抽象统一掉不同工作区的真实信息层级。

## 9. 可访问性与交互规则

- 所有按钮、链接、输入、菜单、tabs、dialogs 和 sheets 可用键盘完成。
- 焦点环在浅深主题均明显，不能只改变背景色。
- 图标按钮必须有可访问名称；不熟悉图标必须有 tooltip。
- 颜色不作为唯一状态，禁用原因在视觉和辅助技术中可读。
- 所有正文与控件满足 WCAG 2.2 AA；大标题不是规避对比要求的手段。
- `prefers-reduced-motion` 下取消位移和渐变过渡，只保留即时状态变化。
- 对话框打开后聚焦标题或首个操作，关闭后回到触发器。
- 流式状态只由一个 `aria-live="polite"` 区域播报，错误使用 `role="alert"`。
- 横向滚动区域可聚焦、有名称，并在内容溢出时提供结构提示。

## 10. 性能与实现约束

- 继续使用现有 React、Radix、Lucide 和自定义 CSS，不引入第二套设计系统。
- 移除产品 UI 中的 Noto Serif SC 使用，并减少不必要字体子集输出。
- 动效只使用 CSS transform/opacity 或现有 Motion 的小型叶组件；若 Motion 仅剩工作区淡入则改为 CSS 并避免主包成本。
- Markdown 与非首屏工作区继续懒加载。
- 长回答自动滚动只在必要时执行，避免每个 token 触发布局抖动。
- 全局 CSS 拆成令牌、基础、壳、共享组件和工作区层，降低 435 个选择器的漂移风险。
- 图片或远程素材不是本次设计依赖；不产生无法追踪来源的生产 raster。

## 11. 实施顺序

5. 重构学业工作区，并隔离各数据请求的加载、错误和空状态。
6. 重构校园服务索引与筛选。
7. 重构审核工作区、tabs、三态分块与发布治理。
8. 同步组件测试、E2E 选择器和必要文档。

## 15. 液态玻璃视觉升级（2026-09-02，用户批准的 addendum）

在保持本规格全部信息架构、契约与响应式验收不变的前提下，视觉层升级为用户选定的「晨雾 × 夜航」双主题液态玻璃（设计源：`.qoder/ui_drafts/draft_c_dual.html`）。本轮改动全部落在令牌与皮肤层：

- **令牌**：`catalog.css` 令牌区对齐 draft（canvas `#eef2f8`/`#0a0f16`、primary `#034ea1`/`#5b9be0`、retrieval `#087680`/`#4fc8ce`），新增玻璃令牌块（`--glass/-strong/-weak/-solid`、`--gborder/-soft`、`--gblur`、`--gshadow/-lg`、`--user-bubble`、`--tt: 0.2s`）；meta theme-color 同步。
- **彩斑**：`body::before/::after` 双层固定 radial-gradient（零 filter），主题切换仅过渡 opacity。
- **玻璃预算**：手机常驻 backdrop-filter ≤2（顶栏+底栏）、桌面 ≤3（索引脊+输入区+临时浮层）；消息列表卡片 0 blur（`--glass-weak` 半透明填充）；`@supports not (backdrop-filter)` 与 `prefers-reduced-transparency` 回退 `--glass-solid`。
- **祖先链禁改**（新增硬约束）：`.app-shell`/`.workspace-transition` 到 body 之间不得加 filter/transform/opacity<1/contain:paint，否则切断 backdrop 采样。
- **浅色主题索引脊**由深色实底改为白玻璃（`--rail-*` 令牌随主题切换）；admin 壳（`.admin-sidebar`）不受影响。
- **验证**：pytest tests/web 132 passed；前端 vitest 22/22；生产构建成功；`scripts/e2e_web_workbench.py` 全矩阵通过（已同步管理后台入口改名：账户菜单「管理后台」→ `/admin` → 「知识审核」导航，`assert_layout` 兼容 `.admin-main`）。验收截图：`docs/qa/glass-p2-*.png`。
