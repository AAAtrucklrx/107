# 小蜗全流程走查（2026-09-17 · 以用户身份实测）

> 方式：真实浏览器（Chromium 1440×900 + 390×844）走用户路径；另做 API/数据库层面的链路核对。
> 覆盖：提问（本地/联网/无解/个人数据/缓存）→ 来源与限制说明 → 未登录与演示身份 → 管理后台（内容队列 / 条目详情 / 发布治理 / 回答反馈）→ 反馈闭环 → 进料预审 → 发布与检索回流 → 运维面。

## 二、问题清单（按严重度）

### P1-1 匿名用户的反馈进了「黑洞」（用户可感知，闭环断裂）
- **现象**：未登录用户点 👎 → 填类型和说明 → 弹窗提示「**反馈已记录**」。但数据库里它落在 `namespace='anonymous'`，而后台列表接口 `WebStore.list_feedback_page()` 只接受 `demo`/`production`：
  ```python
  if namespace not in {"demo", "production"}:
      raise ValueError("invalid reviewer feedback namespace")
  ```
  实测：`anonymous 列表被拒: ValueError: invalid reviewer feedback namespace`。
- **证据**：`answer_feedback` 行 `(3, 'anonymous', 'outdated', 'open', '该次回答涉及 4 条来源，但当前命名空间无法自动处理，需人工查看。')`；管理页「回答反馈」页签与日报「待处理反馈」都看不到它。
- **影响**：比赛演示里**最多的就是未登录用户**，他们以为反馈被记录了，实际永远不会有人处理。
- **建议**：匿名反馈并入 `demo` 审核命名空间（或后台加「匿名反馈」页签）；退一步至少在前端如实提示"未登录提交的反馈仅供统计"。

### P1-2 反馈说明的敏感检测「假阳性」+ 前端弹窗卡死（两个 bug 叠加）
- **服务端**（`api/routers/feedback.py`）：把**画像值当子串**匹配——
  ```python
  profile_values = {str(v).strip() for v in principal.profile.values() if len(...) >= 2}
  if detail and (contains_sensitive_text(detail) or any(v in detail for v in profile_values)):
      raise ApiError(422, "FEEDBACK_SENSITIVE", ...)
  ```
  演示身份的姓名就是「测试」→ 说明里写「这是**测试**说明」即被拒：
  `422 {"code":"FEEDBACK_SENSITIVE","message":"反馈说明包含个人或凭证信息，请删除后重试。"}`
  同理：专业「计算机科学与技术」、年级「2025级」等子串都会误伤。
- **前端**（`ChatWorkspace.tsx::FeedbackDialog.submit`）**没有 try/catch**：
  ```tsx
  const submit = async () => { setStatus("sending"); await apiMutation(...); setStatus("sent"); };
  ```
  抛错后状态永远停在 `sending` → **提交按钮永久禁用、页面无任何报错**（实测 `[role=alert]` 计数 = 0，弹窗仍停在表单）。用户只能关掉弹窗重来，且不知道原因。
- **建议**：① 服务端只拦真正的凭证/身份模式（学号、手机、邮箱、身份证），不要把画像值当子串；② 前端 `try/catch` → 回到 `idle` 并把服务端 `message` 显示出来。

### P1-3 命中语义缓存的回答，反馈无法自动处理（闭环多数情况空转）
- **现象**：缓存回答的来源只剩一条「语义缓存回答」（`display_url` 为空）→ 分诊判定「该次回答没有可追溯的联网来源（未附独立引用），需人工查看」，`status=open`、零自动动作。
- **证据**：走查 5 题里 **3 题**是 `cache_hit`（校历/学籍证明/食堂都显示「缓存 · 语义缓存回答」）；对这些题的反馈实测 `refetch_jobs` 无变化。
- **建议**：语义缓存写入时保留原始 `sources`（含 `display_url`），供反馈回溯与来源展示。

### P2-4 来源降级提案没有全局入口/计数
- 刚生成的 3 条 `draft` 提案（`env/yz/x.ustc.edu.cn`）在「发布治理」页**完全看不到**：该页只有发布状态 + 「导出 Git diff」按钮，没有"待导出 N 条"。提案只在**对应条目的详情**里出现（来源规则建议）。
- **建议**：发布治理页加一行「来源规则建议：N 条待导出」。

### P2-5 管理后台默认落在「工具审核」
- 账号菜单 →「管理后台」进入 `/admin`，页面是**工具审核**（当前 0 条，空态），而主战场「知识审核」要再点一次左侧导航。
- **建议**：默认进「知识审核」，或记住上次访问的页。

### P2-6 联网答案的来源里混进无关项
- 「食堂开放时间」的引用来源含「**中国科学技术大学星座餐厅食堂设备采购更正公告**（中国政府采购网）」，等级标为「独立可靠」。
- 相关性闸门只判断**整体**是否相关，不剔单条；这条采购公告对"开放时间"没有贡献。
- **建议**：对单条来源做主题过滤，或对"采购/招标/中标"类页面降级展示。

### P2-7 进料仍在抓低价值 + 含隐私的页面
- 队列首条：`faculty.ustc.edu.cn/zhangrong12/zh_CN/zhym/651372/list/index.htm`「中国科学技术大学 张荣--中文主页--期末考试」——教师个人主页的临时栏目，含办公电话/邮箱。预审已正确标「稳定性 时效易变 / 敏感性 含敏感信息」，但**进料价值低**。
- 近 24h 日报：进料 82 / 预审 62 / 跑题拦下 17 / 敏感拦下 1。

### P2-8 待审积压增长，且有「本可自动批准」被压住
- `draft 57`、`draft_backlog 66`，最老的 draft 已 **14.5 天**（「合成演示：选课服务时段调整通知」）。
- `auto_eligible 2`、`auto_approved 0`（自动批准开关未开）→ 本可自动过的也在积压里。

### P3-9 今日弹窗（演示身份）每次打开都自动弹且带遮罩
- `todayPopupOpen` 初值 = `personal_academic`，演示身份每次进站都弹；**遮罩会挡住输入框**，不关掉就"打字没反应"（我第一轮走查就误判成 bug，实际是它挡着）。功能上有意为之，但首次体验容易被理解成故障。
- **建议**：首次弹、之后折叠成顶部横幅；或允许"今日不再提示"。

### P3-10 未登录问个人数据时，气泡像「故障」
- 实测气泡：`已进入队列 / 个人学业问题需要先登录。/ 本次回答未完成`
  （服务端是 `401 AUTH_REQUIRED {"message":"个人学业问题需要先登录。"}`，前端把错误直接渲染成消息）
- **问题**：「本次回答未完成」像报错，且**没有登录按钮**。
- **建议**：渲染成引导卡片 + 「进入演示身份 / 科大统一认证」按钮，不要用失败态措辞。

### P3-11 引用上标缺标题时显示裸 URL
- 「相关：https://www.ustc.edu.cn ¹²³」这类行，标题缺失时只剩裸链接。

## 三、健康面（值得记录的正向结果）

- **问答**：校历 0.9s（缓存）、学籍证明 1.3s（缓存）、食堂 5.2s（联网）、未来校长题如实拒答；关掉联网开关（`mode=local`）时，本地答不出的题给「知识库里目前没有收录…请以官方发布为准」，不硬编。
- **索引一致性**：`active 30` = `publish_documents 30`，无"生效却没进索引"或"撤了还在索引"；两批撤回（3+5 条碎片）确认不在索引里。
- **作业**：`publish_jobs` 15 done / 0 非 done；`ingestion_jobs` 63 done / 15 dead（14 OFF_TOPIC + 1 SENSITIVE_CONTENT，属预审正常拦下）；`refetch_jobs` 全部 done，其中一次内容有变化的记为 `ingestion_queued`（回流 ✓）。
- **反馈闭环（登录态）**：`outdated` → `in_progress`「已对 3/3 条来源排队复抓」且 `refetch_jobs 1→4`；`source_issue` → `proposals 0→3`；`helpful` → 直接 `handled`。
- **运维**：6 个服务日志近 2000 行零 `error/traceback`；磁盘 18%；无项目级 crontab（只有系统 timer）。

## 五、建议修复顺序

1. **P1-2**（服务端子串误伤 + 前端弹窗卡死）—— 改动小、影响直接；
2. **P1-1**（匿名反馈可见性）—— 决定"反馈功能到底算不算上线"；
3. **P1-3**（缓存来源回溯）—— 不做的话 P1-1/P1-2 修好后闭环仍多数空转；
4. **P2-4 / P2-5**（治理页提案计数、后台默认页）—— 纯前端，成本低；
5. **P2-6 / P2-7**（单条来源相关性、进料来源治理）—— 需要策略决定；
6. P3 系列按体验优先级排。
