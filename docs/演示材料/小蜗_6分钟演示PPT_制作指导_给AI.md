# 小蜗 · 6 分钟现场演示 PPT 制作指导文件（交付给 AI PPT 生成器）

> **这份文件怎么用**：整份喂给生成 PPT 的 AI。它包含：产品事实（防止画错/说错）、视觉规范、逐页文案与配图指令、
> 真实截图清单与槽位、现场演示剧本。**凡是标「上屏文案」的文字请原样排版；标「生图指令」的交给生图；标「真实截图」的按路径贴图。**
>
> **核心原则（AI 必须遵守）**：
> 1. **所有中文与数字都放在 PPT 文字层，生图里不要出现可读文字**（AI 生图的中文会糊/错字，且数字容易错）；
> 2. 生图只负责**背景、氛围、图标、示意**，风格必须与产品 UI 一致（浅色玻璃拟态 + 深色侧栏 + 蓝色主色）；
> 3. 现场是真机演示，**PPT 是背景板**：每页字要少、图要大、留白多，单页正文不超过 60 字；
> 4. 页码顺序即演示顺序，**S4–S8 会在现场演示时长时间停留**，不要做自动播放动画。

## 一、产品速览（生成文案与配图前必读）

**小蜗 = 中国科学技术大学（USTC）校园 AI 助手**，作品名「小蜗 · 科大学术工作台」，形态是 Web 应用（左侧深色导航栏 + 右侧浅色内容区）。

**它解决的痛点**：校园信息散落在教务处、学校官网、微信公众号里；直接问通用大模型，它会**编**（编时间、编分数、编政策）。

**它的两条底线（全场主线）**：
1. **可核验** —— 答案里的每个数字/日期，都必须能在它披露的来源里找到；
2. **宁可说没数据** —— 查不到就如实说"没有查到可靠数据"，并用「资料未给出」标出无法核实的数字，绝不补写。

**六大块能力（这就是"覆盖广"的骨架）**：

| 能力 | 一句话 |
|---|---|
| 问小蜗（问答） | 本地知识库优先：能本地答就 0.9~1.3 秒答；本地没把握才联网，联网答案带来源与限制说明 |
| 我的学业 | 登录后直接给 GPA、已修学分、成绩单、培养方案、课表（演示数据） |
| 校园服务 | 24 个**经过配置审核**的办事入口 + 活动 + 校园工具 |
| 知识审核后台 | 进料 → LLM 预审（四项判定）→ 人工审核 → 发布（代号可回滚）→ 回流检索 |
| 反馈闭环 | 用户点 👍/👎 → 自动转动作（信息过期→排队复抓；来源有问题→生成来源降级提案；有帮助→办结） |
| 可信工程 | 467 项后端测试 / 34 项前端测试、六项健康检查、演示与生产数据永久隔离 |

**可以放心说的数字（2026-09-17 实测）**：
- 本地命中回答 **0.9~1.3 秒**；联网问答 **4~7 秒**（并行化改造后，改造前 19.7 秒）
- 10 题验收：**10 题作答 / 0 题拒答**，且**作答里"证据中找不到的数字" = 0**
- 已发布索引 30 条条目 ↔ 线上生效文档**完全一致**（无"生效了却没进索引"）
- 后端 `pytest` **467 通过**、前端 `vitest` **34 通过**、readiness 六项健康检查全绿
- 反馈分诊实测：一条"信息已过期" → 自动「已对 3/3 条来源排队复抓」；一条"来源有问题" → 自动生成 **3 条来源降级提案**（可在后台导出 Git diff）

**绝对不要说的（评委一问就穿）**：
- ❌ "覆盖全校所有业务/所有信息" → 事实：索引里是审核通过的有限条目（当前 30 条）
- ❌ "实时同步官方" → 事实：检索 → 审核 → 发布，条目有有效期，过期会自动退出
- ❌ "什么都能答" → 事实：查不到会如实说没数据（**这恰恰是卖点，主动讲**）
- ❌ 把演示数据说成真实学生数据 → 说"演示身份 / 合成演示数据（GPA 3.27、60.5 学分）"
- ❌ 出现任何密钥、内网地址、端口号（演示时注意浏览器地址栏）

## 三、视觉规范

- **画幅**：16:9（1920×1080 或 1280×720）
- **配色**：
  - 背景：`#F6F8FC`（浅冷灰蓝）或纯白；深色页可用 `#0E1626`
  - 主色：`#2563EB`（小蜗蓝）；辅色：`#10B981`（已核验/成功）、`#F59E0B`（提醒）、`#EF4444`（拒绝/风险）
  - 文字：标题 `#0F172A`、正文 `#334155`、注释 `#64748B`
  - 侧栏色（呼应产品）：`#0E1626` 半透明玻璃
- **字体**：思源黑体 / 苹方 / 微软雅黑；英文用 Inter。标题 40–48pt，副标题 24–28pt，正文 18–20pt，注释 ≥14pt
- **版式**：左对齐；每页一个视觉焦点；卡片圆角 16–20px；卡片用白色半透明 + 轻阴影（玻璃拟态）
- **图片风格统一**：扁平 + 轻微渐变 + 细描边，**不要 3D 写实、不要噪点、不要赛博朋克**；插画里**不要出现中文**
- **每页必须留"演示角标"位**：右上角放一个 120×32 的胶囊标签（如「现场演示中」），颜色为主色 10% 透明底 + 主色文字——实机演示时让评委知道"现在看的是真机"

### S9 · 可信与工程
- **上屏文案**
  - 主标题：为什么敢把它放在校园里用
  - 四条：
    - **检验**：后端 467 项 / 前端 34 项自动化测试

## 六、备用页（评委提问时切过去，不占 6 分钟）

### B1 · "联网答案会不会编？"
- 两道闸门：合成前判"资料是否切题"，合成后**逐条核对答案里的数字/日期是否都在来源里**
- 核对不过 → 先让模型改一版；改完仍有 → **就地把那几个数字标成「资料未给出」**，而不是整篇拒答
- 实测：10 题验收里"证据中找不到的数字" **= 0**
- 配图：`06-后台-发布治理.png` 不用；这里用 S4 卡片 2 的大图重排

### B2 · "知识从哪来、会不会脏？"
- 每篇进料都过预审四项：稳定性 / 敏感性 / 重复性 / 相关性；**预审只给建议，人工决定**
- 实测日报示例：某日 进料 82 篇，跑题拦下 17、敏感拦下 1
- 低质碎片条目已撤 8 条；已发布索引 30 条与线上生效文档**完全一致**
- 配图：`04-后台-内容队列与日报.png` 全图

### B3 · "有多快？和通用大模型比呢？"
- 本地命中 **0.9~1.3 秒**；联网 **4~7 秒**（并行化改造前是 19.7 秒）
- 关键差别不是快，而是**快的同时可核验**：来源分四档（官方一手 / 官方公众号 / 独立可靠 / 未核实）
- 配图：一张简单对比条（本地/联网 两条横向条 + 时间数字，数字由 PPT 文字层写）

### B4 · "多人用、数据会不会串？"
- 会话按用户隔离；个人能力需登录；**演示空间与生产知识永久隔离**；未登录只答公共能力
- 配图：`03-未登录问个人数据.png`

### B5 · "为什么需要审核后台，不能全自动？"
- 因为校园信息的代价不对称：**答错一条办事流程，学生要白跑一趟**
- 所以定位是"**机器提速 + 人把关**"：机器做检索、抽取、预审、合成与核对，人决定是否发布、有效期多久
- 配图：S7 流水线图放大

## 七、现场演示脚本（B 的点击路线，务必按序彩排）

### 彩排前必做（5 项）
1. **必须在校园网环境**（演示环境只在校园网可达）；
2. 浏览器：全屏（F11）、缩放 100%、关闭无关标签页与通知；
3. 提前登录「演示身份」并**关掉自动弹出的「今日」弹窗**（不关会挡住输入框，打字没反应）；
4. **预热**：提前把三问各问一遍（语义缓存热了，现场更快更稳）；
5. 准备**备用录屏**（60~90 秒，覆盖三问 + 后台两屏），网络异常时切换播放。

### 三问脚本（S4 时段，共约 80 秒）

| 顺序 | 输入的问题 | 预期 | 让评委看什么 | 讲解要点 |
|---|---|---|---|---|
| ① | `中国科学技术大学2026年校历` | **0.9~1.3 秒**返回教学周表格 | 答案里的表格 + 顶部"缓存/本地知识库"小标签 | "这是本地知识库答的，不到 1.3 秒" |
| ② | `中国科学技术大学食堂开放时间` | 4~7 秒返回，带来源 | **点开「来源 N」**：等级标签、公众号那条的"账号未核实"、限制说明 | "每个数字都能在来源里核对；公众号来源我们标了'未核实'" |
| ③ | `中国科学技术大学2035年校长是谁` | 如实答复："属于未来人事安排，无法给出确定答案" | 答案全文 + 底部「资料未给出」标注（若走联网） | "查不到就说没有 —— 这是我们的底线" |

> 技巧：问 ③ 之前先把输入框左下角的「**联网搜索**」**关掉**，答案更干净（本地说得更利落）；若想顺便展示联网下的诚实标注，就保持打开。

### 后台脚本（S7–S8 时段，共约 105 秒）
1. 账号菜单 →「管理后台」（**注意：默认落在「工具审核」，需再点左侧「知识审核」**——彩排一定要走一次）
2. 停在**进料日报**：念 进料 / 已预审 / 跑题拦下 / 待审积压 / 线上文档 五个数字
3. 点队列**第一条** → 右侧详情：先指「**预审四项**」（稳定性/敏感性/重复性/相关性 + 理由），再指「**原文 / 清洗稿 / 差异**」
4. 切「**发布治理**」页签：指"当前 active 代号"、"上一完整版本"、**回滚上一版本**按钮、"导出 Git diff"
5. 切「**回答反馈**」页签：指一条「处理中」+ 分诊说明"已对 N/N 条来源排队复抓"
6. （可选，若时间富余 20 秒）回到问答页，点一个回答右下角的 👎 → 选「信息已过期」→ 说明写 `开放时间疑似过期` → 提交 → 弹窗"反馈已记录" → 切回后台反馈页签看它出现

### 故障降级话术（**提前背下来**）
- **网络/接口慢**："现场是校园网真实环境，检索偶尔会慢 —— 我先播放预录的同一操作，随后再回来重试。" → 切备用录屏
- **模型答偏**："这正是我们要解决的问题之一。我换一个更明确的问法。" → 换问法，**不要辩解**
- **后台某页空白**：直接切「发布治理」，它有代号与回滚信息，同样能撑住 S7 的论点
- **被追问实现细节**：一句话"这在备用页"→ 切 B1–B5 对应页
