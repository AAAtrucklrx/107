# 2026-08-05 login-e2e（修复 2：端到端登录实测）

## 目标

finding: `login-e2e`。验证「用户统一身份认证后，jw API 能否拿到成绩/课表，响应结构是否与 `course_tools.py` 解析契约匹配」。

## 实测方法

CAS 登录页无法在自动化浏览器中完成（需 2FA）；利用用户浏览器中已存在的 jw 会话（browser-use 复用用户 profile），直接对 jw API 端点发起请求验证响应结构。

## 关键发现

1. **CAS service 白名单（部署级阻塞）**：`http://localhost:8501` 未授权，CAS 登录页直接拦截（显示「应用未对接认证服务」）；`https://jw.ustc.edu.cn` 已授权，可正常显示登录表单。应用内「跳转 → ticket → 回调」链路在部署前不可用（与交接报告一致）。
2. **jw API 按 Accept 头协商响应格式**：浏览器地址栏导航（`Accept: text/html,...`）返回 JAXB XML；`Accept: */*`（requests/fetch 默认）返回 **JSON**。`get_json()` 用 `resp.json()` 解析，走 `*/*` 路径即可正常工作。
3. **成绩学期** `GET /for-std/grade/sheet/getSemesters` → JSON：`[{"id":421,"nameZh":"2026年春季学期","current":false},...]`，与 `_fetch_real_grades` 契约匹配 ✓
4. **成绩** `GET /for-std/grade/sheet/getGradeList?trainTypeId=1&semesterIds=...` → JSON：`{"overview":{...},"semesters":[{"id","scores":[{"courseNameCh","score":"78","credits","gp","courseCode","passed","studentAssoc"}]}],"stdGradeRank":{...}}`，与契约匹配 ✓（score 为字符串、gp 可为 null，解析代码已有容错）
5. **课表** `GET /for-std/course-table/get-data?bizTypeId=2&semesterId={id}&dataId={did}` → JSON：`{"lessons":[{"nameZh":"教学班名","code","credits","scheduleGroupStr","course":{"code","nameZh"},"teacherAssignmentList":[{"person":{"nameZh"}}]}]}`，与 `_fetch_real_schedule` 契约匹配 ✓
6. **student_data_id 提取（新发现的断点）**：home/menu 为 SPA 壳，HTML 不含 dataId（实测 14KB/54KB 页面均无）；课表端点缺 dataId 返回 HTTP 500；成绩接口的 `scores[].studentAssoc` 提供 data_id（实测 504586）。

## 代码改动

- `services/cas_client.py`：
  - 新增 `_resolve_data_id_from_grades()`：从成绩接口提取 `studentAssoc` 作为 data_id 兜底源
  - `_fetch_student_info()`：`_extract_data_id` 失败（SPA 页面无 dataId）时自动走兜底，保证登录后 `get_course_table` 可用

## 验证

- `verify_login_contract.py`（真实响应结构离线契约）：`_fetch_real_grades` 解析 3 条成绩字段正确、gp=None 兜底换算正确（90→3.7）；`_resolve_data_id_from_grades` 提取 504586；`_fetch_real_schedule` 取 `course.nameZh`（而非教学班名）、教师列表、scheduleGroupStr 全部正确 ✓
- `py -m py_compile services/cas_client.py`：通过
- `py init_check.py`：无回归 ✓

## 遗留问题

- 应用内完整链路（CAS 跳转 → ticket → `login_with_ticket` → session）需 CAS service 白名单（部署到 `*.ustc.edu.cn` 域名或向 IT 申请）后才能端到端验证；已确认 jw API 侧契约全部匹配
- `get_course_table_by_week`（`/print-data` 打印格式端点）未实测
- 浏览器导航显示 XML 的现象对调试有迷惑性：验证 jw 端点时应带 `Accept: */*` 或用 requests 默认头
