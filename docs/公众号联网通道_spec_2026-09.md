# 微信公众号联网通道 — 方案 Spec（v1 · 待批准）

> 日期：2026-09-01 · 状态：DRAFT（用户批准后执行）
> 范围：小蜗联网搜索"微信优先"通道（搜狗微信检索 + 正文抓取 + 图片 OCR + 官方号白名单）
> 本文件与既往事实：搜狗 wechat 引擎可返 10 条/次；中间页 JS 拼真实 URL 协议已验证（5/6 成功、0 拦截）；平台 `unlimited-ocr` 已实测（表格图 OCR 成功）；白名单样本「中国科学技术大学」官方号。

## 0. 六个维度

- **Goal**：对"中科大相关"的联网问题，优先检索微信公众号内容并抽取正文与图片信息，以官方号白名单纳入确定性置信门，其余公众号如实降级。
- **Boundary**：新增 `xiaowo_web/evidence/wechat.py` 与管线微信分支、`config/source_trust.yaml` 公众号规则、测试与文档；**不改** Crawl4AI/attestation 纪律、置信门判定算法、隐私净化顺序、预算总上限；**不**引入 JS 执行/浏览器自动化/验证码打码。
- **Acceptance**：① 5 篇真实公众号文章全链抽取（标题/作者/正文 + 图内 OCR 文本（仅含信息图））100% 可通过 mock 单测 + 真实冒烟 4/5 通过；② 官方号文章可确认声明、普通号"已找到未达门槛"；③ 限频压力（10 连发）后仍工作（或按预期进入熔断并自动恢复）；④ pytest 全量绿；⑤ 微信通道任何失败 → 原有通用联网不受影响（熔断隔离验证）。
- **Failure modes**：见 §2（含自反质疑 8 项 + 每项预案）。
- **Priorities**：合规（robots）> 可用性（熔断/降级）> 信息抽取完整度 > 速度；成本兜底（OCR 上限）> 覆盖率。
- **Non-goals**：不做微信登录/个人号自动化；不做验证码打码；不给普通公众号开置信门；不改变"官方 Web 站优先的制度性权威"排序（公众号是补充密度，不是替代权威）；不做历史公众号归档库。

## 1. 执行计划（分 5 步，每步有退出条件）

### Step 0 — 合规与压力实测（先行，不写生产代码）
1. 抓 `https://mp.weixin.qq.com/robots.txt` 与 `weixin.sogou.com/robots.txt`：**若禁止抓取正文 → 微信通道只做"标题+摘要+链接"展示（合规红线，不可绕过）**；
2. 压力样例：同会话 10 连抓（间隔 2s）→ 记录第一次 antispider/环境异常出现位置 → 定标"每窗口阈值"；
3. 图片时效性：跨日重访同一 mmbiz URL 是否 403；
4. 退出条件：robots 结论 + 限频定标数字，若无硬墙则继续 Step 1。

### Step 1 — `evidence/wechat.py`（核心模块）
- `WechatClient`：自持有会话（cookie jar + 浏览器 UA + Referer），全链**独立于 SearXNG**（避免"链接是 SearXNG 会话产出、小蜗无 cookie"导致验证码墙——这是自反出的关键风险点）；
  - `search(query)`：`weixin.sogou.com/weixin?type=2&query=` 取结果（标题/公众号/链接）；
  - `resolve(link)`：同会话+Referer 取中间页 → 解析 JS `url +=` 拼接真实 URL；
  - `fetch(url)`：浏览器 UA + Referer=weixin.qq.com，仅允许 mp.weixin.qq.com 目标（域白名单，防 SSRF）；**手动逐跳跟随（≤5 跳，每跳先过域白名单再请求，2026-09-02 加固）**；超时 20s；302/403/环境异常 → 明确异常类型；
  - `extract_article(html)`：标题/作者/正文文本 + `mmbiz.qpic.cn` 图片列表（去重）；
  - `ocr_images(imgs, max_n=3)`：逐张调平台 `unlimited-ocr`（2.5s 限频、文本阈值 ≥30 字或含 table 才保留，输出标注 `[图N·OCR]`）；失败/403 → 跳过并记录；
- **限频器**（进程级令牌桶）：sogou 请求 ≤1 次/10s、正文 ≤1 次/5s、OCR ≤1 次/2.5s（env 可调）；
- **熔断器**：连续 3 次"验证码墙/环境异常" → 微信通道熔断 10 分钟（env 可调），期间静默回退通用引擎，不报错给用户；恢复窗口后半开探测；
- 全程日志不含用户原始问题（仅 query 摘要/URL/状态码）。

### Step 2 — 管线集成（三处小改）
- **触发词门**：问题命中「科大|中科大|USTC|中国科学技术大学」（正则，隐私净化后）且模式为 web/auto→联网时，走"微信优先分支"（sogou wechat 检索 + 微信链），**其余问题完全走现状**——避免所有联网都变慢；
- **候选顺序**：微信结果 top-5（`choose`：官方号按白名单提权排序）→ 通用引擎结果兜底补齐（≤2 个）；去重（引用 family 哈希机制复用）；
- **信任规则**：`config/source_trust.yaml` 给公众号添加规则——`mp.weixin.qq.com` 域 + 账号名匹配（`中国科学技术大学|科大官方|USTC...` 白名单）→ `official_primary`（或独立级 `wechat_official` 映射到 reliable）；普通公众号 → `unverified`；
- **预算**：微信链计入现有 evidence 预算（30s）；单问答 OCR ≤3 张、公众号 ≤2 篇；超预算 → 只出已得内容（诚实）。

### Step 3 — 测试
- 单测（mock HTTP 层）：搜索无结果 / 链接解析缺片段 / 302 / 403 / 环境异常 / 无文字图过滤 / 熔断触发与恢复 / 限频等待 / SSRF 域拒绝 / 官方号白名单分级 / 非科大问题不走微信分支；
- 集成测试：pytest tests/web 全量（预计 122 → ~135）+ `verify_web_load` 回归。

### Step 4 — 真实验收
- 5 篇真实文章（含 1 篇表格图、1 篇官方号）全链冒烟：字段齐全 + 图 OCR 数据并入 + 引用正确；
- 10 连发压力（模拟比赛演示）→ 观察否触发熔断/封禁及其恢复；记录数字供后续调参。

### Step 5 — 文档与提交
- 规格记录 §11、AGENTS.md 一行、.env.example 新开关（`XIAOWO_WECHAT_ENABLED` 默认关/开——建议默认开但受熔断保护；开关可一键回退）。

## 2. 自反质疑：8 个"没那么简单"的问题与预案

| # | 我之前没说的坑 | 预案 |
|---|---|---|
| 1 | **SearXNG 的链接 vs 小蜗无其会话**：sogou 链接解析强依赖搜索页会话 cookie；若从 SearXNG 结果拿 link 再小蜗抓 → cookie 不匹配 → 大概率验证码墙。**我前测是自己搜+自己解，通过了；换管线路径会复现吗？** | 微信链**完全自持会话**（Step 1），SearXNG 仅用于通用引擎；Sogou wechat 引擎结果不作为微信链输入（仅可保留兜底展示）。Step 0 用"从 SearXNG 取 link 再直抓"复现一次确认差异。 |
| 2 | **熔断/隔离缺失**：优先级实现错了会"微信挂了拖死全部联网"。 | 微信链独立熔断（3 连败→10 分钟冷却）+ 失败静默回退通用引擎；Step 3 有专项测试。 |
| 3 | **robots 合规是硬红线**：Crawl4AI 纪律的延伸——curl 直抓若违反 robots，等于绕开团队自己定的 egress 纪律。 | Step 0 先测 robots.txt；**禁止抓取 ⇒ 只展示标题/摘要/链接**（功能降级，不赌）。 |
| 4 | **触发门过宽 ⇒ 全站变慢**：所有联网都先搜微信（每问 +8~20s），且搜狗压力大增。 | 触发词白名单门（仅科大相关）；其余路径零影响；门控测试覆盖。 |
| 5 | **置信门被"密度大"绑架**：公众号优先 ≠ 公众号说了算。普通号大量事实性内容（数据表）其实质量参差，直接入置信门=风险放大。 | 白名单只认官方号（名单待你给/默认「中国科学技术大学」等知名官方号）；普通号永远 unverified（2 独立可靠也难，去重会拦同源）。 |
| 6 | **图片过期/防盗链/平台 OCR 配额**：mmbiz URL 有时效；unlimited-ocr 是共享平台模型，高频会牵连别的事。 | 403/失败逐一降级；OCR 双层上限（3 张/篇 × ≤2 篇/问答）+ 令牌桶；不做永久缓存，不进知识库（竞品级归档属 Non-goal）。 |
| 7 | **反爬封禁对公网 IP 的连带**：同一出口 IP，搜狗封禁窗口与 baidu/360 相互独立，但**同 IP 共用"数据中心灰名单"风险**——此前我们已把 baidu 打进限流池。 | 微信通道独立低配额（≈1 次/10s）；与通用引擎共用令牌桶分离；封禁观察项（Step 4 压力测试记录）。 |
| 8 | **"优先"语义与既有边界冲突**：用户"信息密度最大"动机是数据（如名单表），但让公众号凌驾官方 Web 站违反"制度性权威"边界；且官方 Web 站抓取有 robots 白名单纪律，公众号没有。 | 语义折中：**检索顺序上公众号优先（密度），置信裁决不变（权威性）**；官方 Web 站与官方公众号同为 official 级，普通公众号不可确认。请用户确认此折中（见 §3 A）。 |

## 3. 需你批准时一并拍板

- **A. "优先"语义折中**：检索优先公众号（密度），置信裁决保持"官方站=官方公众号=一手，普通公众号=未核验"——同意？
- **B. 官方号白名单**：默认「中国科学技术大学」+ 提供式匹配（你补充其他官方号，如 青年科大/科大团委/教务处官方号——**你有名单吗？没有的话先只配「中国科学技术大学」一个**）。
- **C. 参数**：OCR 3 张/篇 × 2 篇/问答；触发词「科大|中科大|USTC|中国科学技术大学」；熔断 3 连败/10 分钟；限频 10s/5s/2.5s —— 同意默认值？
- **D. 开关默认**：`XIAOWO_WECHAT_ENABLED=true`（受熔断保护）还是先 false 灰度？
