### §2 路径对比

| 维度 | 路径 A：API Gateway（Spec 注册，Agent 调用） | 路径 B：UI Launcher（跳转直达） |
|---|---|---|
| 用户体验 | 自然语言直达，无需知道工具存在 | 需用户自己找功能 |
| 实现成本 | 高：Spec + 参数兜底 + `_build_tool_summary` 定制分支 | 低：链接清单 + 入口 |
| 可靠性 | 依赖 LLM 决策（已有确定性兜底路由） | 无 LLM 依赖 |
| 适用工具 | 数据类（查询/计算/推荐，结果回填对话） | 流程类（选课退课/评教/缴费/报修等小蜗无权替代的操作） |
| 架构一致性 | 现有 26 工具即此模式 | 侧边栏模块切换已具雏形 |

**结论：A 为主、B 为辅；B 以 `render_link` 工具实现，成为 A 的子集**——跳转入口由 Agent 按上下文生成（不是静态链接墙），强操作类回答模式统一为「官方入口链接 + 小蜗辅助能力」（例：退课 → 链接 + 模拟退课后学分压力）。

### §3 双通道判定规则（供 think 层实现参考）

```
诉求分类：
├─ 数据查询/计算/推荐/对比 → 路径 A（调对应工具）
├─ 强操作（改变官方系统状态：选退课/评教提交/缴费/报修/请假审批）→ render_link + 辅助工具
└─ 纯咨询（政策/流程/联系方式）→ RAG 检索（含 BM25 负分兜底），必要时补检索（THINK 规则 19）
```

### §4 工具注册协议 v1（P4-1 实现规范）

**Spec 文件**（`tools/ecosystem/{tool_name}.spec.yaml`）：

```yaml
name: eco:gpa_predict          # 生态工具必须 eco: 前缀
display_name: "GPA 预测器"
provider: "张三（PB21xxxxx）"   # 署名，回答中透出
description: "按预期成绩模拟下学期 GPA 与学位绩点"
version: "1.0.0"
permission: read_only          # read_only | write（write 需额外审核）
auth_required: false
params_schema:                 # JSON Schema 子集
  type: object
  properties:
    expected_grades: {type: array, items: {type: string}}
  required: [expected_grades]
result_schema:
  type: object
  required: [source]
source_hint: "本地计算（第三方工具）"
```

**函数签名**（同目录 `{tool_name}.py`）：

```python
def run(params: dict, ctx: dict) -> dict:
    # ctx 由 act 层注入：{"student_id": ..., "semester": ...}（复用参数兜底机制）
    # 返回 dict 必含 "source"（中文标识规范：实时数据/本地缓存/模拟数据/第三方工具）
    ...
```

**注册流程**：文件放入 `tools/ecosystem/` → 加载器校验（schema 完整性 + 签名 + 冒烟调用一次）→ 自动并入 registry → `_build_tool_summary` 走通用 JSON 分支（特殊呈现后续按需加分支）。**投稿审核清单**：无网络外传个人数据、无写操作（除非特批）、source 标识真实、错误路径返回 error 字段而非抛异常。

## 第三部分：技术选型对比

| 决策点 | 选项 | 结论 | 理由 |
|---|---|---|---|
| 前端 | 维持 Streamlit vs 迁 FastAPI+前端框架 | **维持** | 迁移成本高、时间线不允许；卡片用 markdown 表格 + st 组件即可达成目标 |
| Agent 架构 | 单 QA 图 vs 多 Agent 编排 | **维持单图** | 外部实测（WGU Labs）：多 Agent 平均 38s → 单 Agent <5s；现架构已有确定性兜底，无拆分收益 |
| 工具协议 | 自有 Spec vs 引入 MCP | **自有 Spec，语义对齐 MCP** | 校内生态无 MCP 基础设施；保持 params/result schema 兼容 MCP tool 定义，未来可平移 |
| 数据层 | SQLite vs PostgreSQL | **维持 SQLite 双库** | 单机部署无并发压力；双库职责清晰（主库/评课库） |
| LLM | v4-flash 单点 vs 多模型路由 | **单点 + P3-2 降级** | 多模型引入复杂度与不可控性；降级路由已能覆盖可用性风险 |
| 生态工具执行 | 进程内函数 vs 沙箱子进程 | **进程内（试点期）** | 投稿经审核合入，等同内部代码；动态执行沙箱列为远期项 |
