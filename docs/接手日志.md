### 🎯 为什么要改

公众号分支对**非官方号**文章做标题相关性过滤（官方号直接过），判据是“标题含任一核心词”。原来是直接在整句上滑 2 字窗口：

- 跨虚词碎片：`转专业政策是怎样的` → `策是/是怎/怎样/样的`
- 过泛词：`专业`/`政策`/`时间`/`考试` 几乎命中任何校园标题

### ✅ 改法

1. 先删疑问/人称/助词（**长词在前**：`怎么样`→`怎样`→`怎么`… 再到单字 `是/的/了`），窗口不再跨它们生成；
2. 滑窗后丢掉 `_WECHAT_GENERIC_WORDS`（专业/学院/大学/学生/时间/通知/信息/政策/考试/安排/报名/招生/活动/新生…）。

### 📌 教训（值得记住）

1. **「数据在磁盘上」≠「数据在库里」**：`scripts/data/programs_jw/` 有 73,715 行，库里只有 222 行，而 demo 靠 `tmp_fix_3011.py` 能跑通 → **半成品状态被当正常用了半个月**。再遇到「某专业方案是空的」，**先比磁盘数据与库行数**。塌陷发生在 09-03 05:21（爬完）→ 09-04 04:42（首次备份）之间；已排除 `tmp_fix_3011.py`（只删 `program_id=3011`）、9-03 事故（是 `demo/reset` 清空 review.db）、`schema_course.sql`（无 DROP）；**确切机制无法从现存证据复原**（最可能是服务器库从更早的 Windows 状态迁移而来、重爬后未重跑 build 落库）。
2. **改生产库一律「建副本 → 闸门逐表比对 → 原子替换」**，绝不在原地重建（`build_course_db.py --db` 就是为此）。替换前查 `-wal` 是否为空、`lsof` 有无写入者。
3. **`category LIKE '路径%'` 判重会误伤父子路径**（父会匹配到子），要用逐行内容指纹 `(code, category)`。

5. **服务器上 `git push` 必须带 CA**：Watt Toolkit 会中间人解密 github 流量，系统 CA 里没有它的根 → 不加参数就是 `server certificate verification failed (unable to get local issuer certificate)`。仓库内那份 CA 实测可用（`Verify return code: 0`）：
   `git -c http.sslCAInfo=$PWD/scripts/data/steamtools_ca_latest.pem push origin main`
6. **401 先怀疑副本，再怀疑 token（2026-09-16 踩坑 + 当场自我更正）**
   我一度断言「PAT 在 13:11→13:20 UTC 失效、必须换新 token」，**该结论已被推翻**：真因是**我留存的 token 副本被截断**——只有 91 字符，而 fine-grained PAT 标准长度是 **93**；用户重新粘贴完整 token 后 `api.github.com/user` 直接返回 **200**，**token 从头到尾都是好的**。
   **⇒ 报 401 时先核对副本长度（93）、重新取原件，别急着宣布 token 死了。截断的 token 与失效的 token 报错完全相同（都是 `Bad credentials`），「用 Bearer 验一下」根本区分不了这两者。**
   - 报错辨别：`Bad credentials` = 凭据送到了但无效（含副本截断）；`Requires authentication` = 请求根本没带头。**fine-grained PAT 走 `Authorization: basic` 会回误导性的 `Requires authentication`**，所以验 token 一律用 `Bearer`：
     `curl -s -o /dev/null -w '%{http_code}' -H "Authorization: Bearer $PAT" https://api.github.com/user`
   - 非交互 ssh 下 git 无 tty，401 会报成 `could not read Username for 'https://github.com': No such device or address`，**看起来像凭据没配，其实只是 401**，别再花时间找 helper。
   - **已排除代理**：`/etc/hosts` 把 github 域名全指到 `127.0.0.1`（Watt Toolkit 加速），但 `GIT_TRACE_CURL=1` 证实 `AUTHORIZATION` 头确实发出，加速器开不开结果一样。
   - **推送命令（本服务器专用，PAT 用完即弃）**：
     `git -c http.sslCAInfo=$PWD/scripts/data/steamtools_ca_latest.pem -c credential.helper= -c http.extraheader="AUTHORIZATION: basic $(printf 'x-access-token:%s' "$PAT" | base64 -w0)" push origin main`
